IPv4
Формат xxx.xxx.xxx.xxx (4 числа от 0 до 255)

Структура:
Network part(сеть) - xxx.xxx.xxx
Host part (устройства) - .xxx

Маска подсети:
/24 = 255.255.255.0
/16 = 255.255.0.0
/8 = 255.0.0.0

Частные (private) ip-адреса:
Эти адреса используются внутри локальных сетей и не маршрутизируются в интернет:
10.0.0.0 - 10.255.255.255 (Класс А)
172.16.0.0 - 172.31.255.255 (Класс В)
192.168.0.0 - 192.168.31.15 (Класс С)

TCP vs UDP

TCP (Transmission Control Protocol)
Гарантия доставки
Соединение "рукопожатие"
Пакеты приходят в правильном порядке
Медленнее из-за проверок

Используется для SSH(22); HTTP/HTTPS (80,443); FTP(21)

UDP (User Datagram Protocol)
Быстрый
Без соединения
пакеты могут потеряться
не проверяет порядок

Используется для DNS(53); DHCP(67/68); Видеостриминг

Порты

Порт это "номер квартиры" в ip-адресе, он позволяет одному ip запускать много сервисов
Диапазоны портов: 0-1023: системные (well-known)
- 22 - SSH
- 80 - HTTP
- 443 - HTTPS
- 53 - DNS
1024 - 49151: Зарегистрированные
- 3306 - MySQL
- 5432 - POstgreSQL
49152 - 65535: Динамические (эфемерные)
- Используются клиентами для исходящих соединений

DNS (Domain Name System)
Преобразует доменные имена в IP-адреса
- ya.ru - 77.88.55.77
- google.com - 142.250.185.78

Как работает: 
curl ya.ru - система смотрит /etc/resolv.conf - находит DNS-server - Отправляет запрос на DNS-server "Какой IP у ya.ru" - DNS отвечает 77.88.55.77 - Система подключается к 77.88.55.77
Публичные DNS-servers:
Google: 8.8.8.8, 8.8.4.4
CloudFlare: 1.1.1.1
Яндекс: 77.88.55.77, 77.88.8.1

SSH (Secure Shell)
Протокол для безопасного удаленного управления сервером
Проблемы, которые решает SSH:
- Шифрование: весь трафик зашифрован
- Аутентификация: проверка подлинности сервера и клиента
- Целостность: гарантия, что данные не изменены
Как работает SSH с ключами:
- Клиент генерирует пару ключей (приватный + публичный)
- Публичный ключ копируется на сервер
- При подключении:
- Сервер отправляет задачу (challenge)
- Клиент подписывает задачу приватным ключом
- Сервер проверяет подпись публичным ключом
- Если совпало - доступ разрешен
Почему это безопасно:
- Приватный ключ никогда не передается по сети
- Даже если кто-то перехватит трафик, он не сможет расшифровать
- Подделка подписи без приватного ключа математически невозможна

NAT (Network Address Translation) 
Технология, позволяющая множеству устройств использовать один публичный IP
Как работает в VirtualBox:
Мой ПК - VirtualBox NAT - Ubuntu VM
Проблема: VM не видит интернет, но извне (Мой ПК интернет) нельзя подключиться к VM
Решение: 
- Port Forwading: пробросить порт 2222 (Windows) - 22(VM)
- Bridged Mode: VM получает IP из реально сети
