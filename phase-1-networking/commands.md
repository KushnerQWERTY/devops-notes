ip a - показывает все сетевые интерфейсы и их настройки
Вывод на VR: 1: lo: <loopback,up,lower_up> ...
                inet 127.0.0.1 scope host lo
             2: enp0s3: <broadcast, Multicast,Up,lower_up> ...
                link/ether 08:00:27:51:90:be
                inet 10.0.2.15 metric 100 brd 10.0.2.255
lo - loopback - виртуальный интерфейс(сам в себя)
127.0.0.1 - ip loopback - Адрес localhost(всегда этот)
enp0s3 - Ethernet интерфейс - основная сетевая карта
08:00:27:51:90:be - MAC-адрес - Физический адрес сетевой карты             (MAC адрес это уникальный заводской номер сетевой карты (6 пар шестнадцатиричных цифр
10.0.2.15 - IP - адрес в сети VirtualBox NAT                               Первые 3 пары - производитель (в данном случае Oracle/VirtualBox), а последние 3 пары - уникальный номер устройства)
/24 - маска подсети - 255.255.255.0                                        (/24 = 255.255.255.0 - первые 3 числа IP (10.0.2) это сеть , последнее число (.15) - это мое устройство в этой сети
brd 10.0.2.255 - broadcast - Адрес рассылки всем в сети                     В сети 10.0.2.0/24 может быть 254 устройства ( от .1 до .254 )
UP,Lower_up - состояние - интерфейс включен и кабель подключен

ping -c 8.8.8.8 - проверяет связь с удаленным сервером.
Путь: Мой ПК отправляет ICMP Echo Request (эхо запрос) на 8.8.8.8 -> Сервер Google отвечает ICMP Echo Reply (эхо ответ) -> Система измеряет время между отправкой и ответом
Результат: time=37.2ms, 37.1ms, 37.2ms, 38.0ms 0% pocket loss.
Использован 8.8.8.8 потому что это публичный DNS-сервер Google. Он всегда онлайн и отвечает на ping.

Настройка SSH-ключей - Публичный ключ (Public key) - это замок. Приватный ключ (Private key) - это ключ от замка. 
Процесс: Генерация ключа - публичный ключ копирую на Linux - при подключении ssh проверяет, есть ли у меня ключ, который подойдет и если да, то он пускает.
ssh-keygen -t ed25519 -C "comment" - генерация ключа, где -t ed25519 - тип ключа. ED22519 - современный и безопасный алгоритм; -c "comment"  - пометка для чего этот ключ; ssh-keygen - утилита генерации ключей
type $env:USERPROFILE\.ssh\id_ed25519.pub - вывод ключа
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub | clip - копирование в буфер обмена

curl - браузер в командной строке. Он умеет скачивать файлы, проверять сайты, отправлять данные на серверы и тестировать API, не открывая при этом графический браузер.
это утилита командной строки для передачи данных с серверов и на серверы. Она поддерживает множество протоколов: HTTP, HTTPS, FTP, FTPS, SCP, SFTP, TFTP, LDAP, LDAPS, IMAP, POP3, SMTP, RTMP, RTSP и другие.

curl -I - только заголовки (Head request) - отправляет HTTP запрос типа HEAD вместо GET. Сервер возвращает только заголовки, без тела ответа (без HTML/JSON)
Зачем это нужно:
- проверить, работает ли сайт (200, 404, 500, 301)
- Посмотреть метаданные (тип контента, размер, дата)
- Быстрая диагностика без скачивания всего файла
curl -L - Если сервер возвращает код 301 или 302 (редирект), curl автоматически переходит по новому адресу.
Зачем это нужно:
- Многие сайты перенаправляют с HTTP на HTTPS
- или с example.com на www.example.com
- Без флага -L curl покажет только первый ответ 301, а не финальный 200
curl -O - скачивает файл и сохраняет его с оригинальным именем (как на сервере)
